# مدیریت هنرجویان آموزشگاه موسیقی شهرام محذوف

خروجی اول بخش ۱۹: پرونده هنرجو ← ترم خصوصی ← دریافت دستی ← رزرو ← حضور/غیبت/کنسلی ← تکمیل سهم ← تمدید. اطلاعات اصلی در SQLite سرور ذخیره می‌شود.

رابط فارسی و RTL با فونت محلی دانا و طراحی مستقل با الهام بصری از [Metronic 8 Demo 1](https://preview.keenthemes.com/metronic8/demo1/) بازطراحی شده است. طبق درخواست جدید کاربر، بسته اصلی پیش‌نیاز نیست؛ فایل اختصاصی دمو کپی نشده است. پوسته، داشبورد عملیاتی و مدیریت هنرجویان بازطراحی و الگوی مشترک به پرونده، فرم‌ها، ورود و حساب کاربری اعمال شده است. نتیجه بررسی و تصاویر در [وضعیت پروژه](docs/PROJECT_STATUS.md) است.

لیست‌های موجود اکنون با **AG Grid Community** و الگوی لیست محصولات اورنزا پیاده شده‌اند: تم Material با رنگ سفید/طوسی خنثی، RTL/دانا، فیلترهای داخل ستون‌ها، مرتب‌سازی، عملیات آیکونی ثابت و صفحه‌بندی. فیلتر بیرون جدول وجود ندارد. لیست هنرجویان فیلتر/مرتب‌سازی سرور و بازیابی صفحه از URL دارد. استاندارد مشترک در [LIST_UI_STANDARD.md](docs/LIST_UI_STANDARD.md) ثبت است.

ثبت هنرجو صفحه مستقل `/students/new` دارد؛ «ویرایش هنرجو» در گرید یا پرونده به `/students/:id/edit` می‌رود. الگوی فرم اورنزا با بخش‌های اطلاعات، ستون عکس/وضعیت و نوار ذخیره، با رنگ خنثی پیاده شده است. عکس اختیاری JPG/PNG/WebP تا ۵ MiB است؛ پیش‌نمایش، تعویض و حذف با ذخیره فرم انجام می‌شود. تصویر پردازش‌شده داخل SQLite نگهداری می‌شود و همراه بکاپ دیتابیس است. ویرایش برای مدیر/منشی، با کنترل نسخه و حفظ سوابق آموزش/مالی مجاز است.

## پیش‌نیاز و نصب

در «اطلاعات پایه»، نوع تدریس، مدرسین و سازها هرکدام AG Grid سروری و صفحه مستقل ثبت/ویرایش دارند: `/base-data/teaching-types`، `/base-data/instructors` و `/base-data/instruments`. نوع تدریس فهرست مستقلی با عنوان دلخواه است. تغییر وضعیت، فیلترهای داخل گرید، بازیابی صفحه و کنترل نسخه پشتیبانی می‌شوند؛ دسترسی مدیر/منشی است. این فهرست‌ها هنوز انتخاب‌های فرم کلاس/ترم را تغییر نمی‌دهند.

سایدبار دو ورودی مستقیم «کارهای امروز» و «پرونده هنرجویان» دارد؛ پنج گروه دیگر به‌صورت آکاردئونی باز و بسته می‌شوند. منوی مستقل آموزش حذف شده و عملیات آموزشی از مدیریت هنرجویان و پرونده هر هنرجو انجام می‌شود. گروه مسیر فعال پس از ورود/refresh باز است و گزینه‌ها طبق نقش نمایش داده می‌شوند.

همه فرم‌ها عنوان ثابت بالای فیلد و ورودی کوچک `sm` با ارتفاع ۳۸ پیکسل دارند. دراپ‌داون‌ها Select2 واقعی با جست‌وجوی فارسی و RTL هستند. کنترل‌های دوحالته سوییچ دارند؛ بایگانی هنرجو مستقل و انتخاب کسر سهم غیبت صریح است. بسته‌ها محلی‌اند؛ مقدار/گزینه پویا و disabled با Reactive Forms همگام‌اند. فیلترهای لیست‌ها همچنان داخل AG Grid قرار دارند.

Node.js نسخه 24.16.0 (حداقل 24.15 در شاخه 24) و npm. نسخه‌های وابستگی در package-lock.json ثابت‌اند. SQLite از node:sqlite همان Node استفاده می‌کند؛ سرویس دیتابیس جدا لازم نیست.

```sh
npm ci
cp .env.example .env
npm run migrate
```

ساخت مدیر اولیه؛ رمز را در shell وارد کنید تا در تاریخچه فرمان ذخیره نشود:

```sh
read -s 'ADMIN_PASSWORD?رمز مدیر (حداقل ۱۲ نویسه): '
export ADMIN_PASSWORD
ADMIN_USERNAME=shahram npm run admin -- create admin
unset ADMIN_PASSWORD
```

این دستور برای zsh است. در bash از `read -s -p 'Password: ' ADMIN_PASSWORD` استفاده کنید. رمز ثابت و ثبت‌نام عمومی وجود ندارد. از قرار دادن رمز در مخزن خودداری کنید.

## اجرای توسعه

در دو ترمینال از ریشه پروژه:

```sh
npm run api
```

```sh
npm start
```

پنل: http://localhost:4200 — API: http://127.0.0.1:3000. `APP_ORIGIN` باید دقیقاً origin پنل باشد. dev proxy کوکی و API را هم‌مبدأ نگه می‌دارد. از localhost برای ورود استفاده کنید، یا APP_ORIGIN را متناسب با 127.0.0.1 تغییر دهید.

## اجرای build

```sh
npm run build
APP_ORIGIN=http://localhost:3000 npm run api
```

http://localhost:3000 خروجی واقعی Angular و API را از یک سرور ارائه می‌کند. refresh مسیر پرونده پشتیبانی می‌شود؛ assets ناموجود 404 و API ناموجود JSON 404 است. Service Worker فقط shell عمومی را کش می‌کند، نه API یا پرونده و مالی. PWA هنوز مرحله نهایی نصب/آپدیت/بررسی دستگاه‌ها را طی نکرده است. آیکون موقت است و هویت رسمی آموزشگاه نیست.

استقرار عمومی در دامنه این تسک نیست. برای استقرار بعدی: HTTPS در reverse proxy، `APP_ORIGIN` دقیق دامنه و `COOKIE_SECURE=true`، محدودیت دسترسی به فایل دیتابیس، تنها یک نمونه سرور نویسنده، نگهداری بکاپ خارج از میزبان. SQLite برای همین استقرار تک‌نمونه انتخاب شده؛ قبل از استقرار چندنمونه به PostgreSQL مهاجرت شود.

## استفاده از مسیر اصلی

۱. وارد شوید؛ «پرونده هنرجویان» ← «ثبت هنرجو»: نام و نام خانوادگی، تماس خود یا سرپرست و واحد موردنظر. مدیر می‌تواند با دلیل، بدون تماس ذخیره کند. سابقه نامشخص پیش‌فرض است.
۲. داخل پرونده «ترم جدید»: پیش‌فرض ۴ جلسه، شهریه، ارز صریح، تاریخ ثبت‌نام شمسی و محل؛ تک‌جلسه با سهم ۱ همان قواعد را دارد. تخفیف فقط مدیر با دلیل؛ مبلغ صفر با دلیل.
۳. «ثبت پرداخت»: ترم را صریح انتخاب کنید، مبلغ و تاریخ دریافت واقعی و روش. دریافت کمتر مانده ایجاد می‌کند و بیشتر، اعتبار همان ارز. دوباره‌ارسال با شناسه یکسان دریافت جدید ایجاد نمی‌کند. برای انتقال بانکی حساب فعال هم‌ارز لازم است؛ مدیریت حساب‌ها در مرحله مالی آینده تکمیل می‌شود، نقدی نیازمند شماره حساب نیست.
۴. «ثبت جلسه»: ترم، تاریخ شمسی و ساعت تهران. نوبت‌ها خودکار ساخته نمی‌شوند. رزرو از ظرفیت قابل برنامه‌ریزی کم می‌کند، از مصرف کم نمی‌کند.
۵. در جدول ترم «ثبت / اصلاح وضعیت»: حاضر، غایب با انتخاب صریح مصرف و دلیل، یا کنسل‌شده با دلیل و لغوکننده. زمان آینده حاضر/غایب نمی‌شود. نتیجه در سرور اتمیک محاسبه می‌شود.
۶. بعد از مصرف سهم، وضعیت تکمیل‌شده مستقل از بدهی است. «تمدید با مشخصات همین ترم» رکورد جدید با تاریخ و مبلغ قابل ویرایش می‌سازد؛ بدهی و تاریخچه قبلی باقی می‌ماند. پرداخت و جلسه کپی نمی‌شود.

تاریخ‌ها در فرم شمسی با قالب `۱۴۰۵/۰۷/۲۷` هستند؛ ارقام فارسی و لاتین پذیرفته می‌شوند. نمایش شمسی، ذخیره تاریخ ISO؛ زمان جلسه UTC و IANA. API مبلغ رشته‌ای می‌گیرد؛ تومان صحیح، دلار حداکثر دو رقم اعشار؛ ذخیره عدد صحیح تومان/سنت دلار.

## نقش‌ها و امنیت

مدیر همه عملیات این مرحله را دارد. منشی ثبت پرونده/ترم/جلسه/حضور، بدون پاسخ مالی دارد. حسابدار هویت لازم و صورتحساب/دریافت، بدون تغییر آموزشی و جزئیات حضور دارد. نشست HttpOnly/SameSite و CSRF، محدودیت ۵ تلاش ناموفق در ۱۵ دقیقه، رمز scrypt و ثبت AuditLog برقرار است. مدیر در «حساب و دسترسی‌ها» کاربر می‌سازد و غیرفعال می‌کند؛ نشست کاربر غیرفعال قطع می‌شود. آخرین مدیر فعال محافظت می‌شود. تغییر رمز همه نشست‌های همان کاربر را باطل می‌کند.

بازیابی مدیریتی با دسترسی میزبان و رمز محیطی:

```sh
ADMIN_USERNAME=shahram npm run admin -- reset
```

پیش از فرمان، ADMIN_PASSWORD را مانند بالا به‌شکل تعاملی export کنید؛ پس از آن unset کنید. این مسیر در AuditLog ثبت و نشست‌های قبلی باطل می‌شود.

## آزمون و داده نمونه

```sh
npm test
npm run check
npm run build
npx playwright install chromium
npm run e2e
```

روی macOS اگر Google Chrome نصب باشد خودکار برای آزمون انتخاب می‌شود؛ در سایر محیط‌ها Chromium نصب‌شده توسط Playwright استفاده می‌شود. انتخاب صریح با متغیر `PLAYWRIGHT_CHANNEL` ممکن است. نمای موبایل شبیه‌سازی Pixel 7 است، نه آزمون روی دستگاه واقعی. آزمون عملکردی Service Worker را غیرفعال می‌کند؛ نصب/آپدیت PWA هنوز تأیید نشده است.

آزمون API از SQLite حافظه‌ای و سرور تصادفی محلی استفاده می‌کند. آزمون مرورگر از دیتابیس موقت اختصاصی و build واقعی استفاده می‌کند؛ سرور توسعه را نمی‌خواهد. جزئیات نتیجه واقعی در [وضعیت پروژه](docs/PROJECT_STATUS.md).

داده نمونه فقط با اقدام صریح روی دیتابیس خالی:

```sh
DB_PATH=./data/demo.sqlite npm run migrate
# مدیر را با DB_PATH مشابه و رمز محیطی ایجاد کنید
DB_PATH=./data/demo.sqlite npm run seed -- --demo
DB_PATH=./data/demo.sqlite npm run api
```

داده‌ها ساختگی و با نام «نمونه» هستند؛ در اجرای واقعی خودکار بارگذاری نمی‌شوند. سناریوهای گروهی و انتقال دفتر متعلق به مرحله بعدند.

## بکاپ و بازیابی

```sh
npm run backup -- /absolute/path/mahzoof-backup.sqlite
```

بکاپ سازگار با `VACUUM INTO` و شامل کاربران، hash رمز، نشست‌ها، داده و audit است؛ محرمانه نگهداری و رمزگذاری شود. مقصد موجود بازنویسی نمی‌شود. برای بازیابی سرور را متوقف کنید، از فایل فعلی نسخه جدا بگیرید، فایل بکاپ را با نام جدید در data بگذارید و DB_PATH را به آن تغییر دهید؛ `npm run migrate` سپس `npm run api`. فایل SQLite زنده را بدون بکاپ سازگار کپی نکنید (WAL دارد). قبل از استفاده واقعی بازیابی آزمایشی انجام دهید. پیوست/رسید هنوز در این مرحله پیاده نشده؛ در مرحله فایل‌ها بکاپ فایل‌های خصوصی کنار دیتابیس تکمیل خواهد شد.

مرجع دامنه: [بریف کامل](docs/Mahzoof_Music_Codex_Brief.md)، [معماری](docs/ARCHITECTURE.md)، [تصمیم‌ها](docs/ASSUMPTIONS.md).


در صورت کندی رجیستری، `npm ci --prefer-offline --maxsockets=3` از کش استفاده می‌کند. `.npmrc` روش resolution وابستگی‌ها را برای lockfile تثبیت می‌کند؛ تصمیم آن در معماری آمده است.
