## تقویم شمسی و پایان پیشنهادی ترم — ۲۲ اکتبر ۲۰۲۶

همه ورودی‌های تاریخ فعلی (ثبت‌نام، شروع/پایان ترم، سررسید یکجا و اقساط، رزرو/ویرایش جلسه و دریافت واقعی) از directive مشترک `appDatepicker` استفاده می‌کنند. تقویم مستقل با دانا/RTL، انتخاب ماه/سال/روز، امروز/پاک‌کردن، ورودی دستی، اعتبارسنجی تاریخ شمسی، فوکوس صفحه‌کلید، Escape، Alt+ArrowDown و جای‌گیری محدود به صفحه پیاده شد. Reactive Forms همچنان منبع مقدار است و popup هنگام خروج از صفحه پاک می‌شود؛ بسته جدیدی نصب نشد.

با فرض جلسه اول در روز شروع و یک جلسه در هفته، پایان پیشنهادی برابر `شروع + ۷ × (تعداد جلسات − ۱)` روز تقویمی است. تغییر شروع یا سهم، مقدار خودکار را به‌روز می‌کند؛ ویرایش دستی حفظ و دکمه بازگشت به پیشنهاد نمایش داده می‌شود. محاسبه در UTC مستقل از DST و با تبدیل جلالی معتبر است؛ جلسه یا رزرو خودکار ساخته نمی‌شود.

Build و چهار تست مرتبط موفق: دو بررسی محاسبه مرز ماه/سال و اسفند کبیسه/عادی، و دو مسیر کامل دسکتاپ/موبایل شامل انتخاب تاریخ از تقویم، حرکت صفحه‌کلید، تعداد یک جلسه، حفظ پایان دستی، محاسبه مجدد و ذخیره ISO در سرور. تصاویر دسکتاپ/موبایل بازبینی شدند و تقویم داخل عرض صفحه است. تغییر دیتابیس یا API لازم نبود؛ خروجی تازه در نسخه محلی سرو می‌شود.

مدل جدید، ساز و آموزشگاه را مستقل نگه می‌دارد. migration 011 ارتباط‌های جدید و ترجیحات آموزشی، اقساط صورتحساب، شخص درخواست‌کننده و موجه/غیرموجه بودن را اضافه می‌کند. ستون‌ها و رکوردهای قبلی حفظ می‌شوند؛ API قدیمی بر مبنای subject همچنان برای سابقه سازگار است. برای ترم‌های جدید، رزرو و کنسلی و غیبت به دلیل، شخص و تصمیم موجه/غیرموجه نیاز دارند؛ غیبت همچنان تصمیم صریح کسر سهم می‌خواهد. رادیوی حاضر سریع ثبت می‌شود و سایر وضعیت‌ها فرم تکمیلی باز می‌کنند. وضعیت‌های ثابت جلسه، کنترل نسخه، ظرفیت، زنجیره جایگزین و audit حفظ شدند.

تب مالی خلاصه تفکیک ارز، قسط بعدی، AG Grid اقساط/تعهدات، صورتحساب‌ها و دریافت‌های واقعی دارد. تخصیص دریافت به اقساط به ترتیب شماره/سررسید محاسبه و دریافت ناقص یا اضافه طبق رفتار قبلی حفظ می‌شود؛ مبلغ دریافت پیشنهادی از اولین قسط مانده‌دار است. ساخت ترم/قسط دریافت پول نمی‌سازد. اطلاعات مالی در پاسخ منشی وجود ندارد؛ حسابدار اطلاعات حضور و جزئیات آموزشی جدید را دریافت نمی‌کند. ارقام فارسی/عربی برای مبلغ و اعداد سروری و شماره تماس هنرجو/سرپرست/مدرس نرمال می‌شوند.

اعتبارسنجی: build موفق؛ ۴۵ تست کلی API موفق و پس از افزودن سناریوی تمدید سابق، هر ۶ تست اختصاصی گردش موفق؛ دو مسیر کامل مرورگر دسکتاپ/موبایل شامل تشکیل پرونده، حفظ پیش‌نویس، ترم اقساطی، رزرو، کنسلی با دلیل، دریافت ناقص و تمدید موفق‌اند. مهاجرت ابتدا روی کپی بکاپ و سپس دیتابیس اصلی اجرا شد. بکاپ نهایی قبل از اعمال: `data/backups/before-student-workflow-apply-20261022.sqlite`. تمام ستون‌های قبلی در ۲۷ جدول با بکاپ برابرند؛ foreign_key_check خالی و integrity_check=ok، نسخه ۱۱. هیچ داده آزمایشی وارد دیتابیس واقعی نشد. سرور محلی نسخه جدید را روی پورت ۳۰۰۰ اجرا می‌کند؛ کامیت/پوش انجام نشده است.

منوی واقعی `/base-data/payment-methods` در اطلاعات پایه اضافه شد: فهرست AG Grid سروری با ستون‌های عنوان، شیوه تسویه، ریالی/ارزی، تعداد اقساط، توضیحات و وضعیت. ثبت و ویرایش با Reactive Forms، Select2، Floating Label و Switch مشترک است. شیوه تسویه یکجا/اقساطی/بدون شهریه از نوع پرداخت ریالی/ارزی مستقل است؛ اقساطی حداقل دو قسط دارد و ارقام فارسی و عربی پذیرفته می‌شوند؛ بدون شهریه توضیح الزامی دارد و تعداد اقساط/نوع پرداخت در سرور خالی می‌شوند. اعتبارسنجی، کنترل نسخه، audit و مجوز سروری برقرارند. مسیرها و مبالغ/ارزهای پرداخت‌های قبلی تغییر نکرده‌اند؛ اتصال شیوه‌ها به ترم و ساخت برنامه سررسید اقساط در این مرحله انجام نشده است.

مجوز مستقل منو در کاتالوگ نقش‌ها با نوع دسترسی مالی ثبت شد؛ مدیر دائمی خودکار دسترسی دارد و مجوزهای ذخیره‌شده نقش‌های قبلی تغییر نکرده‌اند. migration 010 جدول خالی ایجاد می‌کند. قبل از اجرای آن بکاپ `data/backups/before-payment-methods-20261022.sqlite` گرفته شد؛ پس از مهاجرت، integrity_check=ok و نسخه ۱۰ است. داده‌های ۹ جدول اصلی (هنرجویان، کاربران، نقش‌ها، واحدها، ثبت‌نام‌ها، ترم‌ها، پرداخت‌ها، مدرسین و سازها) با بکاپ برابرند؛ رکورد آزمایشی به دیتابیس اصلی وارد نشده است. build و ۴۰ تست سرور و دو تست مرورگر دسکتاپ/موبایل موفق‌اند. سرور محلی نسخه تازه را روی پورت ۳۰۰۰ اجرا می‌کند.

آخرین بررسی: ۲۱ اکتبر ۲۰۲۶. خروجی اول بخش ۱۹ و بازطراحی مستقل رابط با الهام از Metronic 8 Demo 1 پیاده‌سازی و آزمون شده‌اند. این به‌معنای تکمیل تمام مراحل نسخه اول نیست.

## مدیریت واحدهای آموزشی و اطلاعات تماس اختیاری

۲۱ اکتبر ۲۰۲۶: مقصد `/subjects` از صفحه برنامه‌ریزی‌شده به مدیریت واقعی واحدهای آموزشی تبدیل شد. فهرست با AG Grid طوسی/سفید، فیلتر و مرتب‌سازی داخل ستون‌ها، صفحه‌بندی سروری، وضعیت فقط‌خواندنی و عملیات ویرایش کم‌حجم ساخته شد. مسیرهای جداگانه `/subjects/new` و `/subjects/:id/edit` از Reactive Forms و Floating Label مشترک استفاده می‌کنند. فقط «نام واحد آموزشی» الزامی است؛ آدرس، شماره تلفن، وب‌سایت و آدرس شبکه اجتماعی اختیاری‌اند. وضعیت فعال/غیرفعال با Switch و بدون حذف سابقه مدیریت می‌شود.

migration 008 ستون‌های اطلاعات تماس و version را به جدول موجود `subjects` اضافه می‌کند؛ جدول یا رکورد موازی ساخته نشده و همان واحدهای مورد استفاده ثبت هنرجو و ترم حفظ شده‌اند. API مدیریت جدا از API گزینه‌های فعال فرم‌هاست، فیلتر/مرتب‌سازی allowlist و پارامتری دارد، و ثبت/ویرایش با تراکنش، audit، کنترل نسخه و مجوز منوی `/subjects` محافظت می‌شود. نقش فاقد دسترسی آموزشی در route و API منع می‌شود. واحد غیرفعال در انتخاب جدید نمایش داده نمی‌شود ولی سوابق قبلی حذف نمی‌شوند.

بررسی نهایی: TypeScript و build تولیدی موفق؛ هر ۳۷ تست API موفق، شامل رکوردهای قدیمی، ثبت فقط با نام، افزودن اطلاعات تماس در ویرایش، URL/تلفن نامعتبر، نسخه قدیمی و مجوزها. چهار تست هدفمند Chrome دسکتاپ/موبایل موفق و ۱۲ سناریوی ناوبری/مجوز نیز بدون خرابی گذشتند. فرم واقعی در هر دو اندازه باز و بررسی شد؛ تداخل Floating Label یا سرریز افقی صفحه دیده نشد. تست اولیه موبایل به‌علت مجازی‌سازی ستون خارج viewport در AG Grid انتظار متن نامناسبی داشت؛ بررسی به بازخوانی مستقیم مقدار ذخیره‌شده در فرم اصلاح و اجرای نهایی موفق شد.

پیش از migration واقعی، بکاپ سازگار `data/backups/before-educational-units-20261021.sqlite` با integrity_check=ok و نسخه ۷ گرفته شد. پس از راه‌اندازی نسخه تازه روی پورت ۳۰۰۰، integrity_check=ok، نسخه migration برابر ۸ و هر ۷ واحد قبلی با فیلدهای اختیاری خالی حفظ شدند؛ داده نمونه وارد دیتابیس واقعی نشد. health سرور موفق است. تغییرات محلی‌اند؛ کامیت/پوش انجام نشد.

## بازطراحی مستقل پوسته، داشبورد و هنرجویان — Floating Label

داشبورد: ترتیب شاخص‌ها از جلسات امروز، تعیین وضعیت و تمدید آغاز می‌شود. برنامه امروز و ترم‌های نیازمند تمدید در ستون اصلی؛ حضور و غیاب عقب‌افتاده و مانده مالی در ستون کناری قرار دارند. زیر ۱۲۰۰ پیکسل و در موبایل تک‌ستونی می‌شود. گریدها با ارتفاع متناسب و صفحه‌بندی ۵ ردیفی از فضای خالی زیاد قبلی کم می‌کنند. ساز زیر نام هنرجو نمایش داده می‌شود و فیلتر همان ستون، نام و ساز را جست‌وجو می‌کند. پیام خالی هر بخش متناسب است و همه اعداد و وظایف از API واقعی خوانده می‌شوند. شمارش سهم، بدهی و قواعد دسترسی عوض نشده‌اند.

در بازبینی واقعی موبایل مشخص شد پنج عملیات ثابت، فضای نام هنرجو را بیش از حد باریک می‌کردند. در عرض حداکثر ۶۵۰ پیکسل ستون عملیات هنرجویان از حالت ثابت خارج می‌شود و با پیمایش افقی خود گرید در دسترس است؛ در دسکتاپ ثابت می‌ماند. رندر ستون‌های همین گرید برای پیمایش/تمرکز روی عملیات نگه داشته شد. در کارت باریک دسکتاپ هم صفحه‌بندی بریده می‌شد؛ container query متناسب با عرض خود کارت، انتخاب تعداد و کنترل صفحه را در دو ردیف نشان می‌دهد. پنج تست هدفمند موبایل بعد از این اصلاح در ۸٫۳ ثانیه موفق شدند و تصاویر دوباره بررسی شدند.

## فرم نقش‌ها با چک‌باکس و وضعیت فعال

۲۱ اکتبر ۲۰۲۶: فرم ثبت/ویرایش نقش از گرید سوییچ‌دار به چک‌باکس‌های بومی گروه‌بندی‌شده بر اساس منوهای سایدبار تغییر کرد. هر گروه انتخاب همه و حالت انتخاب بخشی از گروه دارد. چیدمان دسکتاپ دو ستون و موبایل یک ستون است؛ نام نقش و سوییچ فعال‌بودن بالای فرم قرار دارند. انتخاب‌های ذخیره‌شده هنگام ویرایش بارگذاری و قابل تغییرند؛ انصراف تغییری ثبت نمی‌کند. نقش مدیر همیشه فعال و تمام منوهایش انتخاب‌شده و غیرقابل کاهش‌اند. لیست نقش‌ها همچنان AG Grid طوسی/سفید با فیلترهای داخلی است و فقط نام، وضعیت و عملیات ویرایش نشان می‌دهد؛ جزئیات منو و ستون‌های تعداد حذف شدند.

migration 007 ستون active را با مقدار پیش‌فرض فعال به نقش‌ها اضافه کرد. نقش غیرفعال اجازه ورود یا ادامه نشست ندارد؛ تغییر نقش تمام نشست‌های اعضا را ابطال می‌کند. تخصیص جدید نقش غیرفعال در فرم کاربر و API ممنوع است؛ اعضای فعلی و وضعیت مستقل حسابشان حفظ می‌شوند. ویرایش اطلاعات کاربر با نقش غیرفعال قبلی مجاز است ولی آن نقش را فعال نمی‌کند. فعال‌کردن مجدد نقش مجوزهای قبلی را حفظ می‌کند. تغییر فعال‌بودن نقش در فرم با SweetAlert تأیید می‌شود. محافظت مدیر در API و CHECK دیتابیس برقرار است.

پیش از ارتقا بکاپ سازگار `data/backups/before-role-status-20261021.sqlite` گرفته شد. بعد از ارتقا تمام ستون‌های قبلی کاربران، هنرجویان و نقش‌ها با بکاپ برابرند، همه نقش‌های قبلی فعال‌اند و integrity_check=ok است. داده آزمایشی وارد دیتابیس واقعی نشده است. اجرا همان `npm run build` و `APP_ORIGIN=http://localhost:3000 npm run api`؛ migration هنگام شروع سرور خودکار اعمال می‌شود و سرور محلی با نسخه تازه اجرا شده است. تغییرات فقط محلی‌اند؛ کامیت و پوش انجام نشده است.

بررسی اولیه: TypeScript و build موفق؛ ۳۵ تست API موفق شامل غیرفعال/فعال‌کردن واقعی نقش، رد ورود و نشست قبلی، منع تخصیص جدید، حفظ اعضای قبلی و حفاظت نقش مدیر. ۶ تست هدفمند Chrome دسکتاپ و Pixel 7 شبیه‌سازی‌شده در ۱۱٫۵ ثانیه موفق شدند. حالت نیمه‌انتخاب گروه، ویرایش و ماندگاری دسترسی‌ها، وضعیت پس از reload و نبود ستون تعداد منوها بررسی شدند. تصاویر [فرم دسکتاپ](evidence/desktop-role-checkboxes.png) و [موبایل](evidence/mobile-role-checkboxes.png) باز و بررسی شدند؛ تداخل عنوان و چک‌باکس یا سرریز صفحه دیده نشد.

بررسی نهایی: هر ۶۲ تست Chrome دسکتاپ و موبایل در ۱٫۸ دقیقه موفق شدند؛ مسیرهای قبلی هنرجو، جلسات، پرداخت، تمدید، کاربران، رمز و مجوزها هم پاس شدند. نقص عملکردی شناخته‌شده برای درخواست نقش‌ها باقی نیست؛ موبایل فیزیکی بررسی نشده است. هشدار پیشین CommonJS بسته SweetAlert2 در build باقی است و مانع ساخت نمی‌شود. درخواست قبلی پذیرش قوانین همچنان منتظر متن قوانین و پیاده‌سازی نسخه‌بندی/ثبت تأیید است؛ تغییر نقش‌ها آن را تکمیل نمی‌کند.

## تفکیک مدیریت کاربران و جابه‌جایی قوانین ثبت‌نام

۲۱ اکتبر ۲۰۲۶: «مدیریت کاربران» یک گروه مستقل باز و بسته‌شونده در سایدبار، با زیرمنوهای کاربران و نقش‌ها شد. «قوانین ثبت‌نام» از گروه مدارک به تنظیمات منتقل شد؛ عنوان گروه قبلی اکنون «مدارک» است. «آموزشگاه‌های دیگر» از منو، مسیر برنامه‌ریزی‌شده و کاتالوگ دسترسی نقش‌ها حذف شد؛ داده‌های آموزشی قبلی تغییر نکردند. جابه‌جایی قوانین، مجوز قبلی نقش‌ها را عوض نمی‌کند.

build موفق و ۱۶ تست Chrome دسکتاپ/موبایل موفق در ۲۲٫۶ ثانیه، شامل استقلال مدیریت کاربران، قرار گرفتن قوانین در تنظیمات، نبود منوی آموزشگاه‌های دیگر، حفظ نقش‌ها، حفاظت مسیرها و باز و بسته شدن منوها. تصاویر [دسکتاپ](evidence/desktop-menus.png) و [موبایل](evidence/mobile-menus.png) بررسی شدند. سرور محلی با کاتالوگ جدید روی پورت ۳۰۰۰ مجدداً اجرا شد. اجرا: `npm run build` سپس `APP_ORIGIN=http://localhost:3000 npm run api`. کامیت یا پوش انجام نشده است.

باقی‌مانده درخواست: کاربر پذیرش قوانین هنگام ثبت‌نام را الزامی خواسته است. صفحه قوانین فعلاً «در انتظار پیاده‌سازی» است و هیچ متن/نسخه منتشرشده یا سابقه پذیرشی در سامانه وجود ندارد. متن دقیق قوانین از کاربر پرسیده شده؛ تا دریافت آن، تیک صوری یا سابقه پذیرش ساختگی ایجاد نشده و ثبت‌نام فعلی تغییر نکرده است. پیاده‌سازی پذیرش باید متن/نسخه مشخص را نمایش دهد، تیک پیش‌فرض نداشته باشد، ثبت تأیید توسط کارمند را از امضای مستقیم هنرجو متمایز کند و نسخه، زمان و کاربر ثبت‌کننده را در دیتابیس نگه دارد. این بخش هنوز انجام نشده است.

## تأیید SweetAlert و وضعیت فقط‌خواندنی کاربران

۲۱ اکتبر ۲۰۲۶: SweetAlert2 نسخه 11.26.25 نصب شد. تأیید بومی مرورگر حذف شد؛ ذخیره ویرایش کاربر، از جمله قفل/فعال‌کردن حساب، با پنجره فارسی RTL، فونت دانا و دکمه‌های تم تأیید می‌شود. انصراف یا بستن تأیید، پیش‌نویس فرم را حفظ می‌کند و هیچ درخواست تغییر به API نمی‌فرستد. حفاظت آخرین مدیر و ابطال نشست‌ها همچنان در سرور برقرار است.

فهرست کاربران فقط نشان «فعال» یا «قفل‌شده» نمایش می‌دهد؛ سوییچ و تغییر مستقیم وضعیت از گرید حذف شدند. تغییر وضعیت از صفحه ویرایش انجام می‌شود. عملیات کم‌حجم ویرایش و ریست با آیکون کلید حفظ شدند. مودال ریست با دکمه صریح ثبت خودش کار می‌کند. تمام فیلدهای رمز همچنان دکمه چشم مستقل و حداقل ۸ نویسه دارند.

## نمایش رمز، حداقل ۸ کاراکتر و رنگ‌های تم

۲۱ اکتبر ۲۰۲۶: دایرکتیو مشترک appPassword به همه فیلدهای رمز ورود، ایجاد کاربر، ریست و تغییر رمز شخصی اضافه شد. دکمه چشم درون هر فیلد مستقل عمل می‌کند؛ مقدار و محل تایپ را حفظ می‌کند، با کیبورد قابل استفاده است و aria-label/aria-pressed دارد. type=button مانع ارسال فرم هنگام نمایش رمز می‌شود. عنوان ثابت، ورودی sm و جهت RTL فرم حفظ‌اند و متن رمز با فضای جدا از آیکون نمایش داده می‌شود. بستن مودال همچنان رمز را پاک می‌کند.

## ریست رمز در مودال

۲۱ اکتبر ۲۰۲۶: آیکون عملیات ریست رمز در AG Grid به کلید خطی تغییر کرد. کلیک روی آن مستقیماً مودال را روی فهرست باز می‌کند و مسیر صفحه عوض نمی‌شود. فرم ریست زیر فرم ویرایش حذف شد؛ دکمه کلید در هدر ویرایش همان مودال مشترک را باز می‌کند. لینک قدیمی ?password=1 نیز مودال را باز می‌کند. نام حساب مقصد، رمز جدید/تکرار، پیام خطا و دکمه ثبت در پنجره قرار دارند؛ API و مجوز و ابطال نشست قبلی حفظ‌اند. تأیید با دکمه خود مودال انجام می‌شود و confirm مرورگر دیگری ندارد.

مودال از dialog بومی مرورگر برای فوکوس و غیرفعال شدن پس‌زمینه استفاده می‌کند؛ Escape، ضربدر، انصراف و کلیک بیرون آن را می‌بندند و رمز نوشته‌شده پاک می‌شود. هنگام ارسال، بستن موقتاً غیرفعال است؛ خطای سرور داخل پنجره نمایش داده می‌شود و مقدار حفظ می‌شود. پیش‌نویس فرم ویرایش با باز/بسته کردن مودال حفظ می‌شود. خواندن نسخه تازه کاربر در عملیات گرید پس از ریست اصلاح شد تا قفل حساب بدون خروج از صفحه با نسخه قدیمی ارسال نشود.

build و بررسی TypeScript موفق؛ ۸ تست Chrome دسکتاپ/موبایل در ۱۶٫۸ ثانیه موفق: ریست واقعی و ورود با رمز جدید، ابطال نشست، قفل پس از ریست، بستن با Escape و انصراف، بازگشت فوکوس، پاک شدن رمز پس از بستن، نگهداری پیش‌نویس و خطای تداخل نسخه و لینک قدیمی بررسی شدند. تصاویر [دسکتاپ](evidence/desktop-reset-password-modal.png) و [موبایل](evidence/mobile-reset-password-modal.png) باز و بصری بررسی شدند؛ تداخل دیده نشد. سرور، دیتابیس و API این تغییر نیازی به migration ندارند. تغییرات فقط محلی‌اند؛ کامیت/پوش انجام نشده است.

## مدیریت یکپارچه کاربران

۲۱ اکتبر ۲۰۲۶: منوهای «کاربران و نقش‌ها» و «حساب و دسترسی‌ها» با یک منوی «مدیریت کاربران» در گروه مدیریت جایگزین شدند. مسیر /users فهرست واقعی AG Grid با فیلتر داخلی، نقش فارسی، وضعیت سوییچی و عملیات فشرده ویرایش و ریست رمز است. تعریف و ویرایش در /users/new و /users/:id/edit انجام می‌شود: نام کاربری، نقش موجود سامانه، رمز اولیه و سوییچ فعال/قفل. ریست رمز در بخش مستقل همان صفحه ویرایش با تکرار رمز و تأیید انجام می‌شود؛ رمز ذخیره‌شده یا hash به مرورگر برنمی‌گردد.

API فهرست و جزئیات فقط مدیر، ویرایش نام کاربری/نقش/وضعیت و POST /api/users/:id/reset-password پیاده شد. رمز ۱۲ تا ۲۵۶ نویسه است؛ حساب قفل‌شده اجازه ورود ندارد و ریست رمز آن را خودکار باز نمی‌کند. ویرایش، قفل و ریست رمز همه نشست‌های قبلی کاربر را ابطال می‌کنند. آخرین مدیر فعال قابل قفل یا تنزل نقش نیست. فرم‌های جدید نسخه رکورد را برای جلوگیری از ثبت تغییرات قدیمی می‌فرستند؛ نسخه از auth_version موجود خوانده و افزایش داده می‌شود، بنابراین migration جدید لازم نیست. رخدادها بدون رمز یا hash در audit ثبت می‌شوند. حساب خود مدیر نیز با تغییر از نشست خارج می‌شود.

فهرست منو با بخش‌های ۱۳، ۱۷، ۱۹ و ۲۰ بریف تطبیق داده شد؛ عنوان/مسیر گزینه‌های موجود حفظ شد و منوی جدیدی خارج از دامنه اضافه نشد. دو ورودی اصلی «کارهای امروز» و «پرونده هنرجویان» طبق بخش ۱۹ مستقیم باقی‌اند. گزینه‌های دیگر زیر شش گروه آموزش، امور مالی، اطلاعات پایه، قوانین و مدارک، گزارش‌ها و مدیریت قرار دارند؛ هر بار یک گروه باز است و با کلیک دوباره بسته می‌شود. عنوان گروه با آیکون خطی و فلش جهت وضعیت، جای فهرست بلند و همیشه باز را گرفته است.

گروه صفحه فعال هنگام ورود مستقیم، تغییر مسیر یا refresh خودکار باز می‌شود؛ تغییر صرف فیلتر/صفحه در query، انتخاب دستی گروه را به هم نمی‌زند. حالت جمع‌شده دسکتاپ آیکون گروه‌ها را نشان می‌دهد و کلیک روی گروه، سایدبار و زیرمنوی آن را باز می‌کند. دکمه‌های بومی با Enter/Space، aria-expanded و aria-controls کار می‌کنند؛ زیرمنوی بسته در focus و screen reader پنهان است. drawer موبایل، Escape و focus trap قبلی حفظ‌اند. گروه خالی یا گزینه فاقد دسترسی برای نقش نمایش داده نمی‌شود. مقصدهای هنوز ساخته‌نشده همچنان «در انتظار پیاده‌سازی» هستند.

تصاویر واقعی [دسکتاپ](evidence/desktop-accordion-menu.png) و [موبایل](evidence/mobile-accordion-menu.png) باز و بصری بررسی شدند؛ منو خلوت‌تر است و متن و زیرمنو بدون بریدگی نمایش دارند. موبایل شبیه‌سازی Chrome است. نسخه جدید روی سرور پورت ۳۰۰۰ در Chrome باز شد. اجرای معمول: `npm run build` و سپس `APP_ORIGIN=http://localhost:3000 npm run api`؛ نصب و ایجاد مدیر طبق README. API، دیتابیس و قابلیت‌های قبلی تغییر نکرده‌اند. برای این درخواست مورد عملکردی شناخته‌شده‌ای باقی نیست.

## سابقه: دکمه‌های پرونده در ستون عملیات هنرجویان

ستون عملیات هر ردیف AG Grid اکنون «باز کردن پرونده»، «ویرایش هنرجو»، «ترم جدید»، «ثبت جلسه» و «ثبت پرداخت» را با آیکون خطی کوچک، tooltip و نام دسترس‌پذیر دارد. عرض ستون مدیر ۱۹۰ پیکسل است تا پنج دکمه در همان ردیف جا شوند؛ ستون همچنان سمت چپ ثابت است. منشی مشاهده/ویرایش/ترم/جلسه و حسابدار مشاهده/پرداخت را می‌بیند. دکمه‌های داخل پرونده هم برای ادامه کار موجودند.

لینک‌های `students/:id?action=term|session|payment` اطلاعات همان هنرجو را دریافت و فرم موجود را باز می‌کنند. مجوز ورود به عملیات دوباره در پرونده بررسی می‌شود؛ لینک مستقیم غیرمجاز فرم باز نمی‌کند. پارامتر action پس از ورود از URL مصرف می‌شود تا پس از ذخیره، انصراف یا reload خودکار دوباره فرم باز نشود. ویرایش به صفحه مستقل قبلی می‌رود. هیچ ثبت داده با کلیک صرف انجام نمی‌شود و منطق API/دیتابیس تغییر نکرده است.

`npm run check` و `npm run build` موفق؛ **۲۴ تست Chrome در ۵۴٫۲ ثانیه موفق** روی دسکتاپ و موبایل. شش بررسی جدید، عملیات روی هنرجوی درست، جا شدن تمام دکمه‌ها در سلول، بازشدن فرم‌ها، انصراف/reload، ویرایش مستقل و دسترسی نقش‌ها/لینک مستقیم را پوشش می‌دهند. مسیر کامل ثبت تا تمدید، Select2، عکس و گرید نیز موفق‌اند. تصاویر [دسکتاپ](evidence/desktop-student-row-actions.png) و [موبایل](evidence/mobile-student-row-actions.png) باز و بصری بررسی شدند؛ تمام دکمه‌ها داخل ستون قرار دارند. موبایل شبیه‌سازی Chrome است. نسخه جدید روی سرور فعال پورت ۳۰۰۰ ارائه و فهرست در Chrome باز شد. اجرا: `npm run build` سپس `APP_ORIGIN=http://localhost:3000 npm run api`؛ راه‌اندازی اولیه طبق README. برای این درخواست مورد عملکردی شناخته‌شده‌ای باقی نیست.

## سابقه: Select2 برای دراپ‌داون‌های فرم‌ها

مرجع [Select2 مترو‌نیک](https://preview.keenthemes.com/html/metronic/docs/?page=forms/select2) و مستندات رسمی خود Select2 بررسی شدند. `select2@4.1.0` و `jquery@3.7.1` از npm به‌صورت محلی و با نسخه دقیق نصب شدند؛ هیچ فایل اختصاصی Metronic استخراج نشد و وابستگی CDN نداریم. پوسته مستقل سفید/طوسی با دانا، RTL، جست‌وجو، پیام فارسی و عنوان شناور با فضای جدا برای مقدار ساخته شد.

تمام ۱۶ select فرم‌های هنرجو، ترم/تمدید، پرداخت/حساب مقصد، رزرو/جایگزین، حضور/غیبت/کنسلی و نقش کاربر به directive مشترک `Select2` وصل شدند. گزینه‌های پویا، مقدار اولیه و تغییر برنامه‌ای، اعتبارسنجی، حالت disabled و disabled fieldset با Reactive Forms همگام‌اند. رویداد انتخاب به رویداد بومی Angular وصل است؛ هنگام حذف فرم، افزونه، listener و observer جمع می‌شوند. جست‌وجو ي/ك عربی و اعراب را نرمال می‌کند. کنترل‌های فیلتر و صفحه‌بندی AG Grid همچنان متعلق به گرید و داخل خود آن هستند.

بررسی: `npm run check` و production build موفق؛ **۱۸ تست Chrome در ۴۷٫۱ ثانیه موفق** در دسکتاپ و موبایل. تمام انتخاب‌های مسیر ثبت تا تمدید از رابط قابل مشاهده Select2 انجام شدند. جست‌وجوی بی‌نتیجه و فارسی/عربی، انتخاب با Enter و Alt+ArrowDown، Escape، حفظ مقدار پس از خطا، بازخوانی فرم و عکس، گزینه‌های شرطی غیبت/کنسلی، disabled واحد آموزشی تمدید و پاک‌سازی هنگام ترک مسیر آزمون شدند. بررسی تکمیلی وابستگی روش پرداخت/حساب مقصد و مسیر کامل دسکتاپ نیز **۲ تست موفق در ۱۴٫۸ ثانیه** داشت. API و دیتابیس در این تغییر ویرایش نشده‌اند؛ آخرین نتیجه API همچنان ۱۸ تست موفق درخواست قبلی است.

تصاویر واقعی منوی باز در [دسکتاپ](evidence/desktop-select2-search.png) و [موبایل](evidence/mobile-select2-search.png) باز و بصری بررسی شدند؛ خروج منو از عرض صفحه و هم‌پوشانی عنوان/مقدار دیده نشد. موبایل شبیه‌سازی Chrome است، نه دستگاه فیزیکی. نسخه جدید از سرور فعال پورت ۳۰۰۰ ارائه و [فرم ثبت](http://localhost:3000/students/new?ngsw-bypass=true) در Chrome باز شد. اجرا مانند قبل: `npm ci`، `npm run build` و `APP_ORIGIN=http://localhost:3000 npm run api`؛ نصب تازه نیازمند ایجاد مدیر طبق README است. کار عملکردی شناخته‌شده‌ای برای این درخواست باقی نیست؛ استاندارد Select2 برای فرم‌های بعدی در AGENTS.md ثبت شد.

## سابقه: صفحه مستقل ثبت/ویرایش هنرجو و عکس

ثبت از داخل لیست حذف و به `/students/new` منتقل شد؛ ویرایش در `/students/:id/edit` از عملیات گرید یا پرونده باز می‌شود. ساختار فرم‌های اورنزا در پروژه مجاور بررسی شد: بخش‌های اطلاعات در ستون اصلی، کارت عکس و وضعیت در ستون جانبی و نوار ذخیره/انصراف پایین فرم. فرم فعلی همین الگو را با دانا، RTL، Floating Label و رنگ سفید/طوسی پنل دارد. در موبایل بخش‌ها یک‌ستونه‌اند. فرم‌های سایر بخش‌ها در این درخواست تغییر ساختاری نکرده‌اند.

API ایجاد قبلی با JSON حفظ شد؛ multipart به POST و PATCH هنرجو اضافه شد. مدیر و منشی مجاز به ویرایش‌اند؛ حسابدار هم در مسیر و هم API منع می‌شود. کنترل نسخه مانع بازنویسی ویرایش هم‌زمان است. تغییر سرپرست مشترک، اطلاعات فرزند دیگر را تغییر نمی‌دهد. ترم، ثبت آموزشی، بدهی و پرداخت هنگام ویرایش حفظ می‌شوند. migration 002 ستون نسخه و جدول عکس را بدون حذف اطلاعات می‌افزاید.

## سابقه: فیلترهای داخل گرید و تم سفید/طوسی

تمام کنترل‌های بیرونی جست‌وجو و وضعیت هنرجویان حذف شدند. جست‌وجوی جامع (نام فارسی/انگلیسی، کد و تماس) در Floating Filter ستون هنرجو و فیلترهای دیگر در ستون خود AG Grid انجام می‌شوند. لینک‌های q/status و فیلتر نام قدیمی به مدل قابل مشاهده گرید تبدیل می‌شوند. فیلتر و مرتب‌سازی همچنان سروری و صفحه/فیلتر در URL قابل بازیابی است.

فیلتر select ترم بیرون حضور و غیاب نیز حذف شد؛ تمام جلسات پرونده در یک گرید با ستون ترم قابل فیلتر قرار دارند. مسیرهای مستقیم حضور/ترم و عملیات همان رکورد حفظ شده‌اند. رنگ کرم/قهوه‌ای/سبز اورنزا از تم گرید، سرستون، حاشیه، آیکون، popup و hover حذف و سفید/طوسی خنثی جایگزین شد. badgeهای وضعیت معنا و رنگ عملیاتی دارند. فونت دانا و AG Grid باقی‌اند.

این تصمیم جای رنگ‌بندی قبلی اورنزا و هر فیلتر بیرونی را می‌گیرد. `npm run check` و build موفق‌اند؛ `npm test`: ۱۵ موفق. **Chrome: ۱۴ تست موفق در ۳۹٫۵ ثانیه، خروج صفر**؛ نبود کنترل بیرونی، جست‌وجو از Floating Filter، منوی پیشرفته داخل ردیف فیلتر، صفحه‌بندی و بازیابی URL، فیلتر ترم در خود گرید حضور و غیاب و تم سفید بررسی شدند. تصاویر دسکتاپ و موبایل باز و بصری بررسی شدند: [هنرجویان](evidence/desktop-ag-grid.png)، [موبایل](evidence/mobile-ag-grid.png)، [فیلتر ترم](evidence/desktop-attendance-filters.png). production build برابر 797.82 kB خام / 137.84 kB انتقال اولیه است. سرور واقعی با کد جست‌وجوی جدید و همان دیتابیس دوباره اجرا شد و نسخه جدید در Chrome باز شد. فرم‌های ویرایش و داده واقعی تغییر نکرده‌اند.

## سابقه: تبدیل واقعی لیست‌ها به AG Grid

کاربر تأکید کرد **لیست‌های فعلی هم باید AG Grid و مانند محصولات اورنزا باشند**. AG Grid Community 36.2.0 نصب و در lockfile تثبیت شد. کامپوننت مشترک و CSS/ترجمه مرکزی ساخته شدند و لیست هنرجویان، جلسات ترم، صورتحساب‌ها و دریافت‌های پرونده، کاربران، جلسات امروز، حضور معوق و تمدید داشبورد به آن متصل شدند. هیچ جدول HTML یا لیست دستی در این بخش‌ها باقی نمانده است. فرم‌ها و کارت‌های خلاصه ترم و داده واقعی حفظ شدند؛ بخش‌های جدید منو همچنان منتظر پیاده‌سازی جداگانه‌اند.

ظاهر خود grid از مرجع محصولات است: Material، دانا، RTL، رنگ زمینه/سرستون و حاشیه، ردیف ۵۶ و سرستون ۵۲، شماره ثابت راست، عملیات آیکونی ثابت چپ، فیلتر و مرتب‌سازی سرستون و صفحه‌بندی ۱۰/۲۵/۵۰/۱۰۰. در موبایل grid به کارت تبدیل نمی‌شود و پیمایش افقی و عملیات ثابت دارد. جزئیات فنی و مرجع در [LIST_UI_STANDARD.md](LIST_UI_STANDARD.md) ثبت شده‌اند. این تصمیم جای برنامه قبلی «تبدیل در آینده» را می‌گیرد.

API هنرجویان با حفظ قرارداد قبلی به دریافت بلوکی، فیلتر و مرتب‌سازی کل داده در SQLite گسترش یافت؛ نام ستون/عملگر/اندازه بلوک اعتبارسنجی و SQL پارامتری است. داده و مجوزها تغییر نکردند. صفحه و فیلترها پس از reload بازیابی می‌شوند. لیست‌های دیگر از مجموعه کامل مجاز پاسخ‌های قبلی استفاده می‌کنند. فقط تنظیمات ستون‌ها ذخیره می‌شوند، نه اطلاعات پرونده. هنگام بررسی، مسئله بازیابی صفحه پیش از دریافت تعداد کل و شکست نوار صفحه‌بندی موبایل رفع شد.

بررسی جاری: `npm run check` و production build موفق؛ initial برابر 797.85 kB و انتقال 138.04 kB، به‌علاوه chunk مشترک lazy AG Grid برابر ۱٫۱۴ MB خام / حدود ۲۵۸ kB انتقال. `npm test`: **۱۵ موفق**، شامل ۱۲۵ هنرجوی آزمایشی برای صحت sort/filter کل داده، صفحه دوم و بلوک دوم، حروف فارسی، فیلتر ترکیبی، wildcard و رد query نامعتبر. **Chrome نهایی: ۱۴ تست موفق در ۳۷٫۹ ثانیه، خروج صفر**. علاوه بر مسیر کامل و نقش‌ها، ۲۸ هنرجوی ساختگی برای بررسی صفحه‌بندی واقعی، بازگشت به صفحه دوم پس از reload، مرتب‌سازی صعودی کل داده، فیلتر ستونی و بازیابی فیلتر از URL آزمون شدند. ارتفاع ردیف/سرستون، عملیات ثابت و نبود سرریز کل صفحه در دسکتاپ و موبایل بررسی شدند. دو صورتحساب و یک دریافت واقعی در grid مالی، انتخاب ترم از اقدام «ثبت پرداخت»، فیلتر وضعیت «پرداخت جزئی» و لغو فرم بدون تغییر اطلاعات نیز تأیید شدند. فیلتر تاریخ از متن نمایشی شمسی استفاده می‌کند. تصاویر واقعی باز و اصلاح صفحه‌بندی موبایل تأیید شد: [لیست دسکتاپ](evidence/desktop-ag-grid.png)، [لیست موبایل](evidence/mobile-ag-grid.png)، [پرونده](evidence/desktop-profile.png)، [داشبورد](evidence/desktop-dashboard.png) و [کاربران](evidence/desktop-account.png)، [مالی دسکتاپ](evidence/desktop-finance.png) و [مالی موبایل](evidence/mobile-finance.png). همه داده تصاویر ساختگی و backend واقعی موقت است. سرور واقعی با همان دیتابیس برای بارگذاری کد جدید API راه‌اندازی مجدد شد؛ داده یا حساب بازنشانی نشده است.

بخش‌های زیر سابقه تحویل منو و بازطراحی قبلی‌اند؛ استاندارد جاری لیست‌ها همین بخش و LIST_UI_STANDARD.md است.

## سابقه تحویل: منوها و استاندارد اولیه لیست

کاربر خواست ابتدا منوهای کل دامنه ایجاد شوند و سپس بخش‌ها یکی‌یکی ساخته شوند. تمام لیست‌های جدید/بازسازی‌شده باید AG Grid با الگوی لیست محصولات اورنزا باشند؛ جزئیات فرم‌های ویرایش را کاربر برای هر بخش مشخص می‌کند. این قاعده در [LIST_UI_STANDARD.md](LIST_UI_STANDARD.md) و AGENTS.md ثبت شده است.

منوها مطابق بخش‌های ۱۳، ۱۷، ۱۹ و ۲۰ بریف: میز کار؛ آموزش (کلاس‌ها، ترم‌ها، جلسات)؛ مالی (صورتحساب، دریافت، بانک)؛ اطلاعات پایه (واحد آموزشی، آموزشگاه دیگر)؛ قوانین و مدارک؛ گزارش آموزشی/مالی؛ مدیریت (کاربر/نقش، تنظیمات، سربرگ، سابقه عملیات و حساب). منوهای هر نقش فقط در حد دسترسی فعلی نمایش داده می‌شوند و مقصدهای تازه route guard دارند.

۱۷ مقصد جدید فعلاً صفحه «در انتظار پیاده‌سازی» دارند، بدون فرم، لیست ساختگی یا API جدید. سه مسیر عملیاتی قبلی و فرم‌هایشان حفظ شده‌اند. منوی بلند اسکرول مستقل دارد تا مشخصات کاربر و برند در دسترس بمانند. هیچ لیست موجودی در این گام به AG Grid تبدیل نشده؛ نصب و اتصال کامپوننت مشترک آن با اولین لیست انتخاب‌شده انجام می‌شود.

بررسی این گام: `npm run check` و `npm run build` موفق؛ initial برابر 531.77 kB و انتقال تخمینی 103.70 kB. آزمون نهایی Chrome: **۱۲ تست موفق در ۳۳٫۴ ثانیه، خروج صفر**؛ تمام ۱۷ مقصد، هایلایت یکتای مسیر فعال، refresh مسیر، اسکرول منوی موبایل، محدودیت دسترسی منشی/حسابدار و ورود اجباری مستقیم بررسی شدند. چهار تست مسیر قبلی ثبت هنرجو تا تمدید و تاریخ نامعتبر نیز موفق ماندند. تصاویر [منوی دسکتاپ](evidence/desktop-menus.png) و [منوی موبایل](evidence/mobile-menus.png) باز و بصری بررسی شدند. جزئیات بازطراحی قبلی در بخش‌های زیر سابقه بررسی همان تحویل‌اند.

## تصمیم جاری طراحی

کاربر صریحاً پیاده‌سازی مستقل نزدیک به [مرجع Demo 1](https://preview.keenthemes.com/metronic8/demo1/) را خواست و نبود بسته اصلی را غیرمسدود اعلام کرد. این تصمیم جای شرط قبلی دریافت بسته اصلی را می‌گیرد. دمو واقعاً در Chrome باز و تصویرش مشاهده شد؛ فایل اختصاصی قالب از preview استخراج، کپی یا hotlink نشده است. خروجی، پیاده‌سازی مستقل است و ادعای ادغام اصلی Metronic یا تطبیق پیکسلی کامل ندارد. مبنا و منبع دارایی‌ها در [UI_ASSETS.md](UI_ASSETS.md) و [FONTS.md](FONTS.md) ثبت شده است.

## تغییرات این بازطراحی

- پوسته: سایدبار تیره سمت راست با عرض ۲۶۵ پیکسل و حالت جمع‌شده ۸۴ پیکسل؛ هدر خلوت ۷۸ پیکسل، شناسه و نقش کاربر، عنوان، breadcrumb و نوار عملیات مشترک. منوی موبایل با backdrop، Escape، بازگرداندن فوکوس، چرخه Tab و جلوگیری از اسکرول پس‌زمینه.
- داشبورد: شمارنده‌های واقعی هنرجوی فعال، جلسات امروز، حضور معوق و تمدید؛ ساعت تهران و لینک مستقیم حضور؛ جدول ترم با یک جلسه باقی‌مانده یا تکمیل‌شده بدون تمدید؛ بدهی واقعی به تفکیک ارز و مسیر ورود به پرونده برای دریافت. مبلغ بدهی جمعی است؛ گزارش تفصیلی بدهکاران و فیلتر مالی جدید در این تغییر اضافه نشده‌اند.
- هنرجویان: toolbar ثبت، فرم ثبت سریع، جست‌وجو و فیلتر، ردیف دارای هویت هنرجو، شماره با جهت صحیح، badge ظریف و عملیات کوچک؛ صفحه‌بندی و وضعیت جست‌وجوی URL حفظ شده‌اند. در موبایل هر ردیف تمام اطلاعات و دکمه پرونده را زیر هم نشان می‌دهد.
- الگوی مشترک به پرونده، ترم/تمدید، دریافت، جلسه، حضور و غیاب، ورود و حساب/دسترسی‌ها اعمال شد: دانا، آیکون SVG خطی مستقل، پس‌زمینه خنثی، کارت سفید، شعاع ۶–۷ پیکسل، حاشیه ظریف، فاصله‌های منظم و سایه محدود. فونت دانا همان پنج فایل محلی قبلی است.
- Floating Label واقعی داخل کادر؛ عنوان پس از فوکوس/مقدار بالای مقدار می‌رود. select/زمان عنوان ثابت بالا دارند؛ صفر و select غیرفعال تمدید بررسی شده‌اند. خطا بیرون فضای مقدار است.
- API، پاسخ‌های مجاز هر نقش، منطق مالی/آموزشی و دیتابیس واقعی تغییر نکرده‌اند. هیچ seed یا reset روی اطلاعات واقعی انجام نشده است.

## قابلیت‌های خروجی اول

- Angular 22.2.3 standalone، strict، lazy routes و Reactive Forms؛ zoneless/OnPush با اعلان تغییر پس از پاسخ async. Node 24.16، Express و SQLite واقعی با foreign keys، WAL و تراکنش؛ مهاجرت idempotent و بدون نمونه‌سازی خودکار.
- ورود scrypt، نشست HttpOnly/SameSite، CSRF و Origin، rate limit، خروج/تغییر رمز، قطع نشست کاربر غیرفعال، حفاظت آخرین مدیر؛ مدیر اولیه و بازیابی از CLI.
- ثبت هنرجو/سرپرست مشترک، کد خودکار، جست‌وجوی نرمال‌شده فارسی و صفحه‌بندی سرور؛ انتخاب واحد موردنظر، ترم یا صورتحساب خودکار نمی‌سازد.
- مسیر کامل خصوصی: ترم با سهم قابل تنظیم، صورتحساب مستقل، تومان/دلار با مبلغ صحیح، دریافت و تخصیص جدا، اعتبار اضافه و idempotency اتمیک؛ رزرو و ویرایش زمان با ظرفیت/نسخه؛ حضور، غیبت با انتخاب مصرف، کنسلی با عامل/دلیل و جایگزین؛ تکمیل/بازگشایی آموزشی؛ تمدید بدون کپی جلسه/پرداخت و با حفظ بدهی قبلی.
- نقش منشی داده مالی نمی‌گیرد و حسابدار داده آموزشی غیرضروری نمی‌گیرد. تمام کنترل‌ها در سرور برقرارند.

## روش اجرا

برای نسخه موجود ساخته‌شده:

```sh
APP_ORIGIN=http://localhost:3000 npm run api
```

آدرس: http://localhost:3000 — در این اجرا سرور فعال و نسخه جدید در Chrome باز شد. اگر shell قدیمی service worker دیده شد، برای پیش‌نمایش از http://localhost:3000/?ngsw-bypass=true استفاده کنید. حساب و داده موجود حفظ شده‌اند.

برای نصب تازه: `npm ci`، کپی `.env.example` به `.env`، `npm run migrate`، ساخت مدیر با رمز محیطی طبق [README](../README.md)، سپس `npm run build` و فرمان بالا. توسعه با دو ترمینال `npm run api` و `npm start` روی localhost:4200 و APP_ORIGIN متناسب. نمونه‌سازی فقط صریح با `npm run seed -- --demo` روی دیتابیس خالی؛ روی دیتابیس واقعی اجرا نشود. بکاپ با `npm run backup -- /absolute/path/backup.sqlite`.

## کارهای باقی‌مانده

- مطابق مراحل بعد بخش ۱۹: آموزش گروهی/چندمسیره و انتقال افتتاحیه دفتر؛ مدیریت حساب بانکی/اعتبار، اصلاح/ابطال مالی و رسید؛ مجوزهای جزئی؛ قوانین و مدارک؛ PDF سربرگ و گزارش شمسی/CSV و داشبورد تحلیلی.
- گزارش تفصیلی بدهکاران و فیلترهای مالی، مستقل از جمع بدهی و مسیر پرونده موجود، در مرحله گزارش‌ها تکمیل می‌شود.
- PWA نهایی: نصب/آپدیت و offline، آیکون‌های استاندارد و maskable، کش، autofill، بزرگ‌نمایی و صفحه‌کلید روی دستگاه‌های فیزیکی؛ shell-only service worker و manifest موجودند.
- استقرار عمومی انجام نشده؛ SQLite فعلی برای تک‌نمونه است. چندنمونه نیازمند PostgreSQL است.

نبود بسته اصلی Metronic مانع این بازطراحی نیست و درخواست دریافت آن برای این مرحله مطرح نیست.
