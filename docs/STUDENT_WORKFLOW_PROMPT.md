# پرامپت اجرایی

در پروژه فعلی و با استفاده از اجزای مشترک، گردش پرونده هنرجو را تکمیل کن؛ ابتدا کد موجود را بخوان و از بازنویسی بی‌دلیل و تست‌های تکراری پرهیز کن.

- چهار تب اطلاعات فردی، ترم‌ها و جلسات، حضور‌وغیاب و مالی حفظ شوند و پیش‌نویس با تعویض تب از بین نرود.
- ثبت اولیه: ساز، مدرس مرتبط با ساز، نوع تدریس، حضوری/آنلاین، آموزشگاه اجباری برای حضوری، و شیوه پرداخت از اطلاعات پایه انتخاب و ذخیره شوند.
- ساز و آموزشگاه رابطه مستقل داشته باشند؛ سوابق قدیمی بدون حدس‌زدن یا تبدیل خودکار حفظ شوند.
- ترم جدید و تمدید: فرم مرحله‌ای آموزش/جلسات/شهریه با خلاصه پیش از ثبت؛ شماره ترم در مسیر ساز؛ تمدید مشخصات را پیشنهاد کند و بدهی، جلسات و پرداخت‌های قبلی را کپی نکند.
- اقساط: مبلغ و سررسید هر قسط، مجموع برابر شهریه خالص، دقت عدد صحیح تومان/سنت دلار؛ بدون شهریه با توضیح مخصوص هنرجو. ریالی/ارزی مستقل از شیوه تسویه است.
- حضور‌وغیاب: چهار کد ثابت؛ رزرو و کنسلی با شخص درخواست‌کننده، دلیل و موجه/غیرموجه؛ غیبت با تصمیم صریح کسر سهم. رزرو و کنسلی مصرف صفر؛ سابقه، کنترل نسخه، ظرفیت و جلسه جایگزین حفظ شوند.
- مالی: تعهد اقساط از دریافت واقعی جدا؛ نمایش شهریه، پرداخت‌شده، مانده و قسط بعدی به تفکیک ارز؛ دریافت ناقص و اعتبار اضافه، مالکیت هنرجو، حساب هم‌ارز و idempotency حفظ شوند. ثبت ترم دریافت پول ایجاد نکند.
- همه فهرست‌ها AG Grid خنثی RTL/Dana با فیلتر داخلی؛ dropdownها Select2 و فیلدها Floating Label مشترک باشند. مجوز آموزش و مالی در API و رابط حفظ شود.
- بکاپ قبل از migration، تست معنادار API و یک مسیر واقعی دسکتاپ/موبایل، build و اجرای نسخه محلی؛ گزارش کوتاه نتیجه. داده نمونه وارد دیتابیس واقعی نشود.
